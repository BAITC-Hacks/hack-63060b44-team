# Передача проекта HackAlem AI

Инвентаризация от 23.09.2026 описывает фактически имеющиеся файлы. Машиночитаемый список — [handoff_inventory.json](../reports/submission/handoff_inventory.json): относительные пути, размеры, SHA256 оригиналов, манифестов запусков и погодных источников, ссылки на первичные отчёты и результаты сверки хешей. Большие каталоги не копировались, архив не создавался, данные не загружались и не отправлялись наружу. Инвентаризация не является повторным обучением моделей; фактически выполненные вычислительные проверки перечислены отдельно в README и отчёте подготовки к сдаче.

## Что передать

Размеры ниже — несжатые MiB (1 MiB = 1 048 576 байт), без исходного кода и небольших отчётов.

|---|---:|---:|---|
| `data/raw/turbine_1.csv`, `data/raw/turbine_2.csv` | 2 файла | 11,829 | Оригинальные измерения, приложить отдельно |
| `data/weather/noaa_gfs/1p00/` целиком | 8 466 файлов | 371,419 | Полный локальный погодный кэш |
| Снимки из `reports/replay_summary.json` | 29 запусков / 2 784 файла | 293,961 | Все сохранённые выпуски февральского replay |
| Снимки из `reports/validation_observations/folds.json` | 26 / 104 | 357,471 | 13 недельных выпусков × 2 модели |
| Снимки из `reports/validation_coverage6/folds.json` | 26 / 104 | 356,710 | Те же выпуски с покрытием 6/6 |
| Снимки из `reports/validation_weather/folds.json` | 21 / 756 | 265,064 | 7 ежедневных выпусков × 3 модели |
| Снимки из `reports/holdout/folds.json` | 3 / 108 | 37,934 | Один отдельный контрольный выпуск × 3 модели |

Для нового расчёта replay из исходных CSV без сети достаточно кода, конфигурации, файла выбора модели и первых двух строк таблицы: **383,248 MiB**. Если передать также сохранённые 29 выпусков для проверки, получится **677,209 MiB**. Для полного комплекта доказательств всех перечисленных отчётов нужны 105 каталогов запусков: исходные CSV + кэш + эти снимки занимают **1 694,387 MiB (около 1,65 GiB), 12 324 файла**. Точные каталоги перечислены в `artifacts.groups[].entries[].directory` манифеста передачи.

Не требуется передавать весь `artifacts/`: там 132 каталога запусков, всего около 1 671,524 MiB с журналами на момент инвентаризации. Дополнительные 27 каталогов не связаны с пятью первичными отчётами; они перечислены как необязательная история и не удалены. Журналы `events.jsonl` и `artifacts/replay.json` полезны для показа оркестрации, но не нужны для численного `verify-run`. Журналы изменяются при новых запусках; их хеш в инвентаризации относится к моменту её составления.

В будущую сдачу исходников включить `.gitattributes`, `.gitignore`, `README.md`, `config.example.json`, `pyproject.toml`, `requirements.lock`, исходники `windforecast/*.py`, тесты `tests/*.py`, скрипты `scripts/*.py`, документацию `docs/` и отчёты `reports/`. Файлы `data/` и `artifacts/` передаются отдельно от Git по нужному профилю выше. `.venv/`, `.uv-cache/`, `.pytest_cache/`, `__pycache__/`, `*.egg-info/`, `tmp/`, `.env`, `config.local.json` и временные журналы в сдачу исходников не включать. Исключения для данных, снимков, окружения, временных файлов и локальной конфигурации проверены через `git check-ignore` и сохранены в инвентаризации.

## Оригиналы и погода

Локальные CSV побайтово совпадают с двумя предоставленными файлами на Desktop:

| Файл | Байты | SHA256 |
|---|---:|---|
| `data/raw/turbine_1.csv` | 6 049 266 | `c4c341582fb2dd348b7187f0128cff265fe055f469413871ebb5db50eef58b5b` |
| `data/raw/turbine_2.csv` | 6 354 725 | `820578cd18bb557cd30c2e102f3ae5a386dfc6c489a5a15743339c2b017305e5` |

Оригинальные измерения нельзя восстановить из общедоступной погоды или скачать командой проекта. Получатель должен получить оба CSV отдельно; команда `init-data` только копирует их в `data/raw/` и отказывается перезаписывать отличающийся файл. Конкурсный PDF полезно приложить отдельно как постановку задачи; для запуска кода он не требуется. Его имя и SHA256 также записаны в манифесте передачи. Каталога с дополнительными измерениями `data/incoming/` при инвентаризации не было.

Кэш содержит **83 ежедневных цикла NOAA GFS 12:00 UTC с 08.12.2025 по 28.02.2026**, сетка `1p00`. На каждый цикл имеются 17 сроков `f006…f054` с шагом 3 часа: всего 1 411 `source.json`. Каждый срок включает `index.idx`, три среза GRIB2 (`u10`, `v10`, `temperature_k`) и `points-4c84913317e73805.json`. Все 1 411 источников используются перечисленными отчётами. Файлы, требуемые сохранёнными манифестами, присутствуют.

В инвентаризации сверены 105 хешей манифестов с отчётами, 29 хешей прогнозов, 3 751 хеш артефактов внутри запусков, 5 644 погодных файла с их `source.json` и контрольные суммы извлечённых погодных точек. Это проверка целостности сохранённых данных. Архив скачан 23.09.2026; сохранённый `Last-Modified` даёт проверяемую границу доступности объекта, но не доказывает фактическую доставку прогноза команде в исторический момент выпуска. Подробности — [weather-source.md](weather-source.md).

Если кэш потерян, его можно попытаться заново получить **только явной сетевой командой**:

```powershell
.venv\Scripts\python -m windforecast cache-weather --start 2025-12-08 --end 2026-02-28 --horizon 48
```

Начало 8 декабря включает погодную историю для обучающих выборок и январской валидации; загрузки только февральских циклов недостаточно. Команда скачивает отсутствующие объекты и проверяет уже имеющиеся. Повторная загрузка зависит от доступности NOAA и не гарантирует прежние метаданные: время получения будет другим, архивный объект может быть изменён. Новые идентификаторы запусков могут отличаться. При подготовке этой передачи скачивание не выполнялось.

## Приёмка на другом компьютере

1. Разместить исходники, отчёты и выбранные данные с сохранением относительной структуры. Создать новое окружение по README; для зафиксированных снимков использовать Python 3.12.14 и `requirements.lock`. Окружение `.venv` с другого компьютера не переносить. Установка зависимостей сама может потребовать сеть; при полностью автономной установке нужен отдельно подготовленный набор установочных пакетов, которого эта передача не создаёт.
2. Сверить SHA256 обоих оригинальных CSV и манифестов с `handoff_inventory.json`. Не редактировать сохранённые манифесты ради замены старых абсолютных путей.
3. Выполнить аудит и расчёт с `--weather cache`. Команды ниже не обращаются за погодой в сеть. `audit` обновляет локальный `reports/data_audit.json`, а `forecast`/`replay` создают или переиспользуют локальные снимки и дополняют журнал, поэтому приёмку проводить в полученной рабочей копии.

```powershell
.venv\Scripts\python -m windforecast audit
.venv\Scripts\python -m windforecast forecast --issue "2026-01-31T23:00:00+05:00" --weather cache
.venv\Scripts\python -m windforecast replay --start 2026-01-31 --end 2026-02-28 --weather cache
```

Проверить исходные первый и последний снимки можно независимо от расположения проекта:

```powershell
.venv\Scripts\python -m windforecast verify-run artifacts/runs/a587f5347a6fc4512eec87fc
.venv\Scripts\python -m windforecast verify-run artifacts/runs/638d72d758e42d7cb5b6686d
```

`verify-run` читает сохранённый `manifest.json`, проверяет все файлы из `artifact_sha256` и заново обучает модель по `hourly_inputs.csv` и погодным CSV-снимкам. Для этой численной проверки исходные CSV, внешний погодный кэш и сеть не нужны; передавать нужно **весь выбранный каталог запуска**, в том числе `model.pkl`, который также проверяется по хешу. Это не заменяет проверку полной цепочки происхождения погоды и новый расчёт из исходных измерений.

Код `windforecast/*.py` должен иметь `source_version` **`4676e85e83ed56ed37cde375feb716045755c55ae64dd394c42a4bd3fa3885ba`**; версии шести проверяемых библиотек должны совпадать с `manifest.environment`. Другие версии приводят к явной ошибке `verify-run`. `.gitattributes` сохраняет байты Python-исходников при переносе через Git, поскольку перевод окончаний строк тоже меняет этот хеш.

В старых манифестах и `folds.json` сохранены абсолютные пути исходной Windows-машины. `verify-run` использует переданный каталог и файлы внутри него, поэтому эти пути не нужно переписывать. Для нового расчёта `config.example.json` разрешает пути относительно своего нового расположения. Абсолютные пути входят в происхождение запуска и его идентификатор: после переноса `forecast`/`replay` могут создать новые `run_id` даже при тех же числах. Исходные ID, хеши и отчёты следует сохранить как доказательство первоначального результата.
